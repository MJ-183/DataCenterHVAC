# Claude Code 프롬프트 — Phase 19 실측 비교 (아래 전체를 복사해 붙여넣기)

---

## 목표

Phase 19 **"실측 비교"**를 만들어 주세요. 실제 데이터센터의 장기 실측(시간 단위)을 같은 조건의 시뮬레이션과 비교합니다. 결과물은 다섯 가지입니다.

1. 항목별 오차
2. 시뮬 A → B 보정 단계 설명
3. 항목 × 실행별로 나눈 비교 그래프
4. OpenAI 오차 원인 진단
5. 화면의 새 탭

`validation_esif/` 폴더의 스크립트가 이미 동작하는 **프로토타입**입니다. 이걸 앱 기능(백엔드 모듈 + API + 화면)으로 옮기는 작업입니다. 먼저 아래를 읽고 시작하세요.
- `validation_esif/README.md`
- `out/calibration_steps.md`
- `out/summary.json`
- `esif_compare.py`, `calib_steps.py`, `structure.py`, `sensitivity.py`, `ai_diagnose.py`, `plots.py`

## 지켜야 할 규칙

- **엔진 수식(hvac/engine.py)은 바꾸지 않습니다.** 고도 보정 습구나 고정분 보조동력 같은 개선 후보는 분석 결과로만 보여 주세요. 수식 변경은 별도 승인을 받습니다.
- **기존 결과는 소수점까지 그대로 유지합니다.** `tests/snapshots`와 기존 테스트가 모두 통과해야 합니다.
- **모르는 값은 만들지 않습니다.** 시나리오 입력마다 출처를 `사실(출처)` 또는 `가정`으로 붙이세요. 기존 provenance 구조를 재사용합니다.
- **오차 부호는 프로젝트 기존 규칙을 따릅니다.** 기존 규칙은 `hvac/validation.py`의 **계산 − 실측**이고, 양수면 시뮬이 과대입니다. 프로토타입은 G14 원래 부호(실측 − 계산)라서 NMBE 부호가 반대입니다. 화면과 응답 모두 기존 규칙으로 통일하고, 화면에 정의를 한 줄로 표시하세요.
- **AI는 계산하지 않습니다.** 서버가 계산한 근거 묶음만 보내고, 응답 숫자는 `hvac.insights.unverified_numbers`로 대조합니다. 프로젝트 AI 해설과 같은 원칙입니다.

## 1단계 — 백엔드 (여기까지 하고 멈춰서 보고)

### 1-1. `hvac/realdata.py` — 실측 데이터 모델

**일반 형식:** 시간 단위 표입니다.
- `timestamp`(현지 표준시), `it_kw`(필수), 계측 항목 열 여러 개, (선택) 외기 `dry_bulb_c`, `rh_pct`
- 기존 `hvac/tabular.py`·`itdata.py`의 열 자동 매칭을 재사용해, 열 이름과 값 모양으로 후보를 제안하세요.

**항목 매핑(mapping):** 실측 열 → 시뮬 전력 키 묶음입니다.
- 예: `{"cooling_kw": ["tower_fan"], "pump_kw": ["chw_pump","cw_pump","liquid_pump"], "hvac_kw": ["crah_fan"]}`
- PUE 정의도 매핑에 둡니다. 예: `pue_terms: ["it","cooling_kw","pump_kw","hvac_kw","plug_and_light_kw"]`, `ups_loss: 0`

**ESIF 프리셋:** `backend/data/real_presets/esif.json`
- 데이터는 `data_esif/esif_hourly_mst.csv`를 사용합니다.
- 매핑, 시설 사실과 가정(아래 표), 기간(보정 2016-09-01 ~ 2017-08-31, 검증 2019)을 넣으세요.
- 기상은 현장 외기 파일(`data_esif/esif_outside_hourly_mst.csv`)이 있으면 그것을, 없으면 `validation_esif/golden_tmy3.epw`(TMY3)를 씁니다. 어느 쪽을 썼는지 날짜별로 집계해 결과에 넣으세요.

| 구분 | 설정 | 근거 |
|---|---|---|
| 사실 | hybrid_dlc, liquid_fraction 0.794 | NREL: IT 0.91 MW = 액체 HPC 0.76(발열 95% 이상 액체) + 공랭 0.15 MW |
| 사실 | tcs_supply_c 24 / tcs_return_c 35 | NREL: 24 ℃ 공급, 35~40 ℃ 환수 |
| 사실 | ups_loss_ratio 0 | NREL PUE 집계 5항목에 전기 손실 없음 |
| 사실 | floor 929 m², lighting 4 W/m² | 10,000 ft², 실측 조명·콘센트 3.7 kW (입력) |
| 사실 | IT = 실측 it_power_kw | |
| 가정 | 외피 최소, 외기 1,000 m³/h, 공기측 코일 21/27 ℃, 나머지 계수 기본값 | 공개 자료 없음 |

**데이터 확인 장치:** 기간 실측 PUE를 매핑으로 다시 계산해 원본 `pue` 열과 비교하세요. 차이 중앙값이 0.001을 넘으면 경고합니다.

### 1-2. `hvac/real_compare.py` — 비교 엔진 (엔진 호출만, 수식 변경 없음)

- **`run(scenario, dataset, mapping, periods) → 결과`**
  - 날짜별로 `simulate_days`를 실행합니다. IT는 실측 시간값, 기상은 위 규칙을 따르고, 결측 IT는 하루 안에서 보간합니다.
  - 실행 3가지:
    - **A:** 사실 + 기본 계수
    - **B:** 보정 기간에서 계수 비례 보정
    - **C:** B 계수를 검증 기간에 적용
- **항목별 지표 (실측이 있는 시간만):**
  - 평균 kW, 비율(시뮬 ÷ 실측), NMBE, CV(RMSE). G14 공식이되 자유도는 n−1, 부호는 위 규칙입니다.
  - 시간 상관, IT와의 상관(실측/시뮬), 습구와의 상관(실측/시뮬)
  - 월별 표, 기간 PUE, 칠러 필요 시간(실측 칠러 대수가 0이면 0 h와 비교), WUE
  - G14 판정(시간: |NMBE| ≤ 10%, CV ≤ 30%)
- **`calibration_steps(A, B, C)` — 화면에 그대로 쓰는 구조화 출력.** `out/calibration_steps.md`와 같은 내용이어야 합니다.
  - 0단계: 바꾸는 것 / 두는 것 / 방법. 기존 Phase 12 LM 보정과 무엇이 다른지도 적습니다.
  - 1단계: 항목별 실측 평균, A 평균, 비율 r, 계산식 문자열
  - 2단계: 계수별 A값 × r = B값. r은 반올림 전 평균의 비율입니다.
  - 3단계: 재실행 확인. 잔차와 함께, 계수 결합으로 남는 잔차(팬 발열 → 방열량 → 냉각탑 팬·냉각수 펌프)를 설명 문장으로 생성합니다.
  - 4단계: PUE 기여 분해. 항목별 (시뮬 − 실측) ÷ IT 평균을 구하고, A에서 과대·과소가 상쇄되는 경우를 자동으로 문장화합니다.
  - 5단계: 검증 기간 적용 결과와 G14 판정
  - 문장은 템플릿으로 만들고 숫자는 계산값만 넣습니다. LLM은 쓰지 않습니다.
- **`structure_check()`:** 실측 = 고정분 + a·IT + b·max(습구, 0) + c·max(−건구, 0) 최소제곱(numpy)
  - 보정 기간에 맞추고 검증 기간에 적용해, 엔진 비례 보정과 NMBE·CV를 비교합니다.
  - 고정분 비율도 함께 냅니다. 이것은 **분석용**이며 엔진에 넣지 않습니다.
- **`sensitivity_chiller_hours()`:** `validation_esif/sensitivity.py`와 같이 해수면 습구 vs 사이트 고도 대기압 습구, 접근온도 변경별 칠러 필요 시간을 계산합니다.
  - 고도는 시나리오 site에 `elevation_m`(선택)를 추가합니다. 엔진은 이 값을 쓰지 않고 분석에만 씁니다.
- **성능:** 365일 × 3회가 컨테이너 기준 약 18초 걸립니다. 결과는 (시나리오 해시, 데이터 해시, 기간) 키로 디스크 캐시하세요(`store` 패턴 재사용).

### 1-3. `api/real_compare.py` (`main.py`에 router 등록)

- `GET  /real/presets`: ESIF 프리셋 목록과 설명
- `POST /real/inspect`: CSV 업로드 → 열 후보, 매핑 제안, 기간 범위, 결측 비율
- `POST /real/compare`: {preset 또는 dataset_id, mapping, periods, scenario_overrides} → run 결과 + calibration_steps + structure + sensitivity
- `POST /real/diagnose`: {compare_id} → OpenAI 진단
  - `api/ai.py`의 `get_llm()`과 `LLM.parse`를 재사용합니다. 키가 없으면 503을 반환합니다.
  - 응답 스키마는 `validation_esif/ai_diagnose.py`의 `Diagnosis`/`Cause`를 옮깁니다(`basis: data | hypothesis`, 영향 항목, 방향, 근거, 확인 방법, 모델 수정).
  - 근거 묶음은 사실·가정 표, 항목 매핑 정의, A/B/C 지표, 월별 A 표, 보정 단계, 구조 검증, 칠러 민감도, 출처 기준값(NREL WUE 0.7 / 냉각탑만 1.42, 방열 비율 47/42/11%)입니다.
  - 응답의 `unverified_numbers`와 사용 모델명을 함께 반환하고, compare_id별로 캐시합니다.
  - 시스템 프롬프트는 `ai_diagnose.py`의 SYSTEM 규칙을 그대로 쓰되, **부호 규칙 문장**을 추가하세요.

- **합성 데이터:** 엔진 출력에 알려진 배율(냉각탑 1.5, 펌프 0.4, 팬 3.0)을 곱해 '실측'을 만듭니다. B 보정이 배율을 1% 안으로 회복하는지 확인하세요. 팬 결합 잔차가 있다는 점을 고려합니다.
- **G14 공식:** 손계산 배열로 NMBE·CV 값과 부호를 확인합니다.
- **매핑 PUE 재계산:** 원본 pue와 일치하는지 확인합니다.
- **calibration_steps:** 단계 0~5가 모두 있고, 숫자가 결과 지표와 같은지 확인합니다.
- **`/real/diagnose`:** `tests/test_ai.py`의 FakeLLM 패턴을 씁니다. 근거 없는 숫자가 `unverified_numbers`로 잡히는지, 키가 없을 때 503인지 확인합니다.
- **ESIF 프리셋 스모크:** 7일 구간 fixture(작은 CSV)로 API가 끝까지 도는지 확인합니다.
- **기존 테스트와 스냅샷은 그대로 통과해야 합니다.**

## 2단계 — 화면 (승인 후)

상단 PAGES에 `["real", "실측 비교"]`를 추가하세요(최적화 다음). 컴포넌트는 `frontend/src/components/RealCompare/`에 둡니다.

1. **DatasetPanel**
   - 프리셋 선택(ESIF) 또는 CSV 업로드
   - 매핑 편집 표: 실측 열 ↔ 시뮬 키, PUE 항목 체크
   - 기간 선택(보정·검증)
   - 기상 출처 표시(현장 / TMY3, 날짜 수)
2. **ConditionTable**
   - 시나리오 입력을 `사실(출처 링크)` / `가정` 배지로 표시
   - 가정값은 수정 후 다시 실행할 수 있게 합니다.
3. **SummaryTable**
   - 행: PUE, 항목별 평균 kW, 기계 합계, 칠러 시간, WUE
   - 열: 실측 / A / B / C
   - 비율과 NMBE·CV를 표시하고, G14 통과/미통과는 아이콘 + 글자로 표시합니다(색만으로 표시하지 않음).
4. **SplitCharts — 범례를 나눈 비교 그래프 (recharts)**
   - **소분할 격자:** 행 = 항목(냉각탑계, 펌프, 공조 팬, 기계 합계, PUE), 열 = 실행(A, B, C)
   - **칸마다 두 선만:** 실측 + 해당 실행. 범례도 **칸마다 따로** 둡니다. 범례는 선을 가리지 않는 위치(그래프 위 머리줄)에 둡니다.
   - **칸 머리줄:** 왼쪽에 실행 이름과 기간, 오른쪽에 평균 차(%, PUE는 절대값)
   - **축과 색:**
     - 같은 행은 y축 범위를 공유합니다. **이중 축은 쓰지 않습니다.**
     - 색은 실측 `#222831`, A `#9aa5b1`, B `#1f6fd1`, C `#d9822b`로 하고, 실행마다 고정합니다(순서가 바뀌어도 색 유지).
   - **조작:**
     - 시간 단위 전환: 월 평균 / 일 평균 / 임의 1주 시간값
     - 칸에 마우스를 올리면 툴팁에 실측·시뮬·차이를 함께 표시합니다.
   - **추가 그래프 두 개:**
     - 항목별 실측 vs 시뮬 시간값 산점도 + 1:1 선 (실행 선택)
     - IT vs 기계 전력 산점도 (실측 / 시뮬을 나란히 두 칸). 고정분 구조를 보여 줍니다.
   - 정적 예시: `validation_esif/out/fig5_split_compare.png`
5. **CalibrationSteps**
   - 단계 0~5를 카드로 보여 주고, 각 카드에 표와 설명 문장을 넣습니다(백엔드 `calibration_steps` 그대로).
   - "B 계수를 시나리오에 적용" 버튼을 둡니다. 기존 적용·되돌리기 규칙을 따르고, provenance는 `calibrated(real:esif)`로 남깁니다.
6. **DiagnosisPanel**
   - "OpenAI로 오차 원인 분석" 버튼. `/ai/status`가 꺼져 있으면 비활성화하고 이유를 표시합니다.
   - 원인 카드는 순위, `근거 있음` / `가설` 배지, 영향 항목, 방향, 근거, 확인 방법, 모델 수정 순으로 보여 줍니다.
   - `unverified_numbers`가 있으면 경고 띠를 표시합니다. 모델명과 생성 시각도 표시합니다.
   - AI 결과 아래에 서버 계산 근거(구조 검증, 칠러 민감도 표)를 함께 보여 줘서 사용자가 대조할 수 있게 합니다.
